### 默认多 Agent 协作与委派（自动生效）
- **主会话零噪音与防膨胀原则（Clean Main Session）**：主会话只保留**与用户交互、当前计划与决策、追踪 subagent 进展、最终结果对齐**；**主会话禁止裸跑全量 `npm test` / `pytest` 等大输出测试**（避免与全局规则 2.3/2.4 冲突，全量测试/评测跑批统一走 `coder` 通道，主会话只收 5–10 行结构化摘要：通过/失败数、关键指标、失败定位与报告路径）。同时遵守 3 条防膨胀约束：
  - **主会话不代读参考源码**：写 `coder` 简报只写「目标 + 验收 + 允许范围 + 失败日志路径 + 已知根因」；需要代码位置时只派一次 `scout` 返回 ≤30 行「文件:行号」地图，不把源码片段抄进简报。
  - **大快照 / 单行超大文件不裸 diff**：凡 `*.snap`、`*snapshots*.json`、`package-lock.json` 等文件，禁止主会话直接 `git diff`，交由 `scout` 或 `coder` 按键级比对返回 ≤10 行摘要。
  - **免重复通读 `SKILL.md`**：本核心片段已覆盖常规 `--role coder` 派发、等待与验收规则，无需每场会话重复通读完整 `SKILL.md`；仅在涉及 `--resume`、`load_config.sh` 或故障排查时按章节局部读取。
- **Read vs Act 默认分工（硬边界）**：
  - **`scout`（纯只读分析）**：仅限代码地图、大日志/测试报告根因定位、大快照 diff 摘要、文档盘点。**明文禁止**派原生 `research` 跑需要本地端口或家目录配置的测试套件（只读无网沙盒会触发 `fetch failed` / `EPERM` / 悬挂句柄）。
  - **`fast`（轻量小活）**：一两个文件、无需先读代码定位、一轮改完自验的细微确定性改动。
  - **`coder`（统一 Act 执行通道）**：通过 `run_delegate.sh --role coder` 派发给配置里的 coder 通道，统一承担：多文件代码实现 + 自测闭环、**全量测试/评测跑批与失败排查**、**常规 Git 整理与收尾**（核对 `git status` / `git diff --stat`、按白名单路径精准 `git add`、分批 `git commit`、仅在用户明确授权时 `git push`）。**默认主动执行，无需用户每次提醒。**
- **原生 `invoke_subagent` 与跨 Harness `run_delegate.sh` 的硬边界（不混用）**：
  - **需要写简报或执行 Act 闭环的任务一律走 `coder`**（多文件实现、新增多个测试、带测试闭环修 Bug、全量测试/评测跑批、常规 Git 收尾）：调用 `run_delegate.sh --role coder` 派发，保护主订阅额度。**不要因为 `Model="flash"` 便宜就把这类任务写成原生子代理**——换成 `flash` 只是换了档位，活仍在 AGY 里，也没有 coder 的测试闭环。
  - **Plan/Execute（Orchestrator）模式与 `coder` 交接**：多文件实现、新增多个测试、带测试闭环的 Bug 修复或全量测试/评测验收，规划模型在 `exit_plan_mode(plan=...)` 中**不要把逐文件改写或全量跑测派给 AGY 执行模型在主会话手写/裸跑**；应把执行计划写成「把五段式简报与输出 JSON 默认落盘到 `<artifactDirectoryPath>/scratch/`（免工作区外写权限弹窗、不污染 `git status`，守卫自动放行）或 `DELEGATE_SCRATCH_DIR` → 后台调用 `bash ~/.agents/skills/multi-agent-delegation/scripts/run_delegate.sh --role coder ...`（`NotificationTimeoutSeconds` 设 900 以上）→ 完成后做最小 diff 与测试摘要验收」。**单任务直接 `--dir .` 改当前工作区、靠 `git diff --stat` 验收；仅并发多写任务才开 `git worktree`**。首次在无 `.agents/delegation/config.env` 的非 Python 项目委派前，先检查并补齐项目级 `DELEGATE_DEFAULT_TEST_CMD`（示范：`npm test,npm run,node --test,git status,git diff,git log,git add,git commit`，按需可追加 `,git push`，但无用户明确指令严禁 `git push`，严禁 `--force` / `git reset --hard`、禁止 `git add -A` / `git add .`），避免 `coder` 遇 `permission_denials` 或因传 `--test-cmd` 触发审批弹窗。仅单点小改（数行以内、1–2 个文件）或纯文档同步才由执行模型直接在主会话完成。
  - **只读分析（`scout`）与 `fast` 级小活**：优先原生 `invoke_subagent`。只读分析显式指定 `TypeName="research"`（仅读源码/日志/大快照摘要，**禁止跑测试套件**），控制单个子代理粒度（2–3 分钟内可完成，先列清单与行号索引、勿整仓通读），纯清单/目录/检索优先用 `Model="flash_lite"`，需推理排查再用 `Model="flash"`；`fast` 级小活（一两个文件、不需要先读代码定位、一轮改完自验）可用 `TypeName="self"` 加 `Model="flash"`，守卫为 `deny` 时会被拦截、改走 `coder`。
  - **不要用 `invoke_subagent(Model="inherit")` 派子任务**（即使 tool schema 的默认值是 `inherit` 也不沿用）：守卫 Hook 会按 `DELEGATE_INHERIT_SUBAGENT` 把它改写成轻量档，或直接拦截。
- **分层配置优先**：执行委派前按 `项目级 (.agents/delegation/) > 用户级 (~/.config/multi-agent-delegation/) > 核心 MD > Skill 默认值` 读取角色绑定与偏好覆盖，适配用户本机实际的订阅组合（如 AGY / Claude Code + 智谱 GLM / DeepSeek / Cursor）。
- **例外与升级**：仅极小单点改动（数行以内、无探索成本）由主会话直接完成；`coder` 连续 2–3 轮自修仍不绿时熔断升级 `heavy`；高风险架构或复杂权衡先由主会话提炼高密度上下文，再主动建议调用 `architect`（只读 Plan 模式）联合决策。
- **配额降级与会话复用**：若某外部渠道额度耗尽或报错，自动降级到兜底角色（默认 `fast`）并在本会话内熔断故障通道；同主题/同模块多轮任务优先复用已有 subagent（`send_message`）或 CLI `--resume <id>`，避免反复新建会话。`run_delegate.sh` 失败时输出是一份 `status: "failed"` 的 JSON 报告，按其中的 `attempts[].reason` 与 `next` 处理（守卫策略允许时改用原生子代理，`deny` 下由主会话接手），不要原地重跑同一条命令。
- **等待被委派的任务**：`run_delegate.sh` 的输出文件只在结束时写入，运行期间是 0 字节、`git status` 没变化都属正常。多文件任务可能跑十几分钟，开头几分钟往往只有读取和检索；`NotificationTimeoutSeconds` 设 900 以上。收到通知后用 `bash ~/.agents/skills/multi-agent-delegation/scripts/run_delegate.sh --progress <out.json>` 查进度（进程是否还在、已用时、工具调用次数和最近一次调用）；**仍显示 `running` 且没有 `status: "failed"` 报告，就不要 kill 后自己接手**。真要接手，先确认它不再显示 `running`。
